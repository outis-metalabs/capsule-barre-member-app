Decisions

Confirmed · 9 Oct 2026

OD-6

Extend a pass: real operation, or hold in disguise?

Today expiry moves only by releasing a hold. "Extend 7 days" as a hold freezes the pass for 7 real days and is refused whenever she has a class booked.

Decided: add an owner-only extend with reason and audit log. The app never changes expiry.
serverbiggest
OD-7

Do expiry / low-balance pushes need owner approval?

Today the SMS reminder waits for the owner to approve a task.

Decided: booking, deadline and class-change pushes fire automatically. Expiry and low-balance follow the same rules as the SMS but need no approval; SMS is suppressed when she has a device — one channel per event.
serverdesk process
OD-1

Does SMS opt-out block the login code?

The activation and login code is authentication, not marketing.

Decided: no — the code always sends.
server policy
OD-2

How strict is the name match at activation?

Phone + name must match a live member row.

Decided: trim spaces, then exact. No fuzzy match. Copy: "use the name on your contract."
serverapp copy
OD-3

Which studio opens first for a two-studio member?

Decided: the studio of her most recently active pass; switch is one tap away.
server
OD-4

Same phone registered twice in one studio?

The server warns but never blocks, for money-history reasons.

Decided: keep the server as is; quick-add defaults to use existing on a phone + name match.
desk process
OD-5

Capture consent at registration for the app?

SMS opt-out, marketing and app push are three different things.

Decided: no change — the app needs none of them.
desk process
OD-8

One display status for a pass?

Status + date alone cannot tell the app whether a refunded or voided pass is usable.

Decided: yes — ACTIVE · HELD · EXPIRED · VOID · REFUNDED · ENDED in the member projection.
serverapp copy
OD-9

Who says which pass a booking will use?

Several active passes are consumed earliest-expiry first.

Decided: the server returns it per class; the app labels, never computes.
